# Oil Spill Detection using Machine Learning
### SAR image semantic segmentation | VS Code | Python | PyTorch | Streamlit

This project trains segmentation models to identify possible oil-spill pixels in Synthetic Aperture Radar (SAR) images. It uses paired SAR images and pixel-level masks. It is **not a tabular classification project**.

## Dataset

Kaggle dataset supplied for this project:
https://www.kaggle.com/datasets/bitsandlayers/sar-oil-spill-segmentation-dataset-sos

The SOS dataset is an image-segmentation dataset. The commonly documented refined Deep-SAR SOS release contains 6,455 training and 1,615 validation image/mask pairs, with 256×256 SAR images and binary masks. Check the downloaded Kaggle version and its directory layout before training; dataset revisions can differ.

The refined dataset is also described at:
https://zenodo.org/records/15298010

### Download the dataset

Option A — Kaggle website:
1. Open the Kaggle URL above and sign in.
2. Click **Download**.
3. Extract the archive.
4. Copy the extracted `images` and `masks` folders into `data/raw/`.

Expected layout:

```text
data/raw/
├── images/
│   ├── train/
│   └── val/
└── masks/
    ├── train/
    └── val/
```

The loader also supports `data/raw/train/images`, `data/raw/train/masks` and corresponding `val` folders. Image and mask files must have matching filename stems (e.g. `sample_001.png`).

Option B — Kaggle API (Windows):
1. Install Kaggle CLI: `pip install kaggle`
2. Create an API token in Kaggle: Account settings → API → Create New Token.
3. Place `kaggle.json` in `%USERPROFILE%\\.kaggle\\kaggle.json`.
4. From the project root run:

```powershell
kaggle datasets download -d bitsandlayers/sar-oil-spill-segmentation-dataset-sos -p data/raw --unzip
```

If Kaggle extracts nested archives, extract those too and arrange the folders as shown above. Never share your Kaggle API token.

## Project deliverables

1. Problem statement and dataset: SAR-based pixel-level oil-spill segmentation.
2. Data dictionary and EDA: image/mask inventory, image dimensions, pixel distributions, sample grids and mask coverage.
3. Preprocessing and baseline: grayscale conversion, resizing, robust per-image intensity scaling, paired geometric augmentation, compact U-Net.
4. Model evaluation: Small U-Net and U-Net compared using Dice, IoU, pixel precision, pixel recall and pixel accuracy.
5. Final report and notebook: generate metrics/plots and document actual measured results; do not report invented scores.

## Run

First inspect that the dataset is paired and correctly located:

```powershell
python -c "from src.data import find_pairs; print('train pairs:',len(find_pairs('data/raw','train'))); print('val pairs:',len(find_pairs('data/raw','val')))"
```

Create EDA inventory and sample visualizations:

```powershell
python -m src.eda --data data/raw
```

Train both models (GPU recommended):

```powershell
python main.py --data data/raw --epochs 20
```

Evaluate on validation data:

```powershell
python -m src.evaluate --data data/raw --split val
```

If a labelled test split exists:

```powershell
python -m src.evaluate --data data/raw --split test
```

Generate the concise PDF results report after evaluation:

```powershell
python -m src.report
```

Launch UI:

```powershell
streamlit run app.py
```

## Hardware and runtime

Training is substantially faster with an NVIDIA GPU and a compatible PyTorch CUDA build. CPU training is supported but may be slow. Start with `--epochs 1` to verify the pipeline. Reduce batch size in `config.py` if you run out of GPU/CPU memory.

## Metrics

- **Dice**: overlap measure between predicted and ground-truth oil pixels.
- **IoU**: intersection divided by union.
- **Precision**: fraction of predicted oil pixels that are correct.
- **Recall**: fraction of ground-truth oil pixels detected.
- **Pixel accuracy**: fraction of all pixels classified correctly.

Oil spill pixels can occupy a small fraction of an image, so accuracy alone is misleading. Prioritize Dice/IoU and recall alongside precision.

## Important limitations

- The model outputs a pixel mask, not a confirmed incident report or geographic oil-spill boundary.
- The current loader converts images to grayscale and resizes them to 256×256. This is suitable for the common SOS tile format but does not preserve full geospatial metadata.
- The validation split should be used for model selection. Use a separate untouched test set for final reporting when provided.
- The two neural models are academic comparison baselines; broader comparisons (e.g. DeepLabV3) can be added after verifying hardware and dataset compatibility.
- Probability values are not calibrated confidence unless a calibration procedure is performed.
